# 岗位精选

一个无依赖、只读的中文岗位快照网站。分别展示人工选择继续了解的线索与自动采样候选、信息完整度、待确认事项，以及 BOSS直聘、字节跳动招聘官网或猎聘的原始岗位链接。采样候选不等于合格推荐。

## 使用

- 默认打开“今日新增”，可切换到“近7天新增”或“全部岗位”。使用浏览器当前时间对应的 `Asia/Shanghai` 日历，近7天包含今天及前6天；今日/近7天不包含未来收录时间。全部岗位保留所有当前记录。
- 结果按 `firstPublishedAtById` 首次公开展示日期从新到旧分组；没有该映射的旧记录回退到 `firstSeen`。组内再按初筛参考分、首次观察时间或了解优先级排序。展示时间、观察时间与源站发布时间分开，不使用最新快照生成日重算旧岗位的新增日期。
- 日期视图可与关键词、工作内容方向、了解优先级、本轮新增标记及可选月薪区间组合。视图按钮中的数字不含其他筛选条件，筛选结果与每个日期分组另列匹配数量；重置会清除可选条件并回到“今日新增”。
- “今日新增”与“本轮新增”不同：同日早晨新增3条、中午新增2条，则今日共5条，本轮为2条。相同来源及岗位 ID 的重复观察不重复计新。今日无新增会明确提示，可主动查看近7天或全部岗位，不会暗中改为展示全部。
- “按工作内容选方向”保留岗位原标题，方向依据已阅读的 JD 实际职责归类；同一岗位名可能做不同工作。方向选项来自当前数据，不根据标题自动分类。
- 关键词搜索覆盖页面展示的标题、公司、方向、职责摘要、任职要求、入选参考与待确认事项等信息。可先尝试“渠道市场”“区域市场”“需求生成”等中文方向或职责词；其中“渠道市场”“生态市场”也可找到已归为“伙伴营销”的岗位。英文别名仅是本站的可选搜索便利，例如 Field Marketing / Regional Marketing 可找到“区域市场”，不是源站搜索建议。别名仅辅助查找已归类的岗位，不是自动分类器；英文大小写和词间空白不影响匹配，短英文缩写按单词边界匹配。可用空格组合别名与其他关键词，所有条件需同时满足。
- “产品市场”方向也支持“产品营销”、Product Marketing、PMM 等可选搜索别名，仍以已审核的职责归类为准。
- “品牌活动”方向支持“活动营销”“活动策划”、Event Marketing 等别名，不根据标题自动归类，也不代表伙伴营销或商机转化职责。
- “内容营销”方向支持“内容市场”、Content Marketing 等站内查找别名，仍以实际职责和记录中的分类为准。
- 组内优先级排序依次为“优先了解”“有条件匹配”“转型备选”，其他或未知优先级排在其后；同级按初筛参考分、首次收录时间排序。不按优先级隐藏岗位，默认组内按初筛参考分排序，不改变日期分组的新旧顺序。
- 薪资仅作参考，默认无薪资门槛且保留月薪未公开或不可比较的岗位。可比较月薪按区间交集筛选，单位为 K（千元/月）；也可只看可比较月薪，或只看未公开/不可比较的岗位。薪资保留“招聘页标注”，可能含提成、奖金等浮动部分；不猜测未知薪资，不根据标注薪数推算保底年薪。只有薪资原文、没有可比较月薪数值时仍展示原文，但不会解析数字后假定单位，也不将其当作零薪资。
- 展开“任职要求与记录”可阅读要求、工作语言说明、详情阅读状态和时间记录。
- “展示状态”默认包含已选入与采样候选，也可只看其中一类；信息完整度及来源筛选可独立组合。未读、详情不完整、身份冲突或方向不明的有效岗位卡片默认仍可见，不伪装成“有条件匹配”。候选不计算匹配分，职责方向只依据可核对的源站文本。
- 原始岗位在新窗口打开，可能需要登录源站。本站不提供账号、投递、状态标记或数据上传，不保存筛选条件。

这是只读岗位快照，网页本身不会运行采集。可选的[本机定时采样服务](scheduler/README.md)按北京时间 09:30、12:30 进行有界 BOSS 采集。显式启用 `candidate-feed` 后，每轮有效岗位卡片脱敏、去重后自动公开，不以私有方向/资格判断或事前人工审批阻挡展示；完整 JD 读取额度仍有限。明确人工排除的 ID、非法身份与隐私不安全数据不公开。`collection-only` 仍是兼容的仅私有采集模式，不会在升级时自动变成发布模式。所有模式都不是 AI 学习、全市场覆盖或资格认证，具体条件仍以源站/招聘方为准。

## 本地浏览

使用任意静态 HTTP 服务打开 `docs/`，例如：

```sh
python3 -m http.server 8000 --directory docs
```

访问 `http://localhost:8000`。请勿直接双击 HTML 文件：浏览器通常不允许以 `file://` 方式读取模块和 JSON。

## 文件

| 路径 | 用途 |
| --- | --- |
| `docs/index.html` | 页面结构与岗位卡片模板 |
| `docs/styles.css` | 自适应深灰与金色主题 |
| `docs/app.mjs` | 安全渲染、交互和数据读取状态 |
| `docs/model.mjs` | 数据契约、筛选、排序和时间格式化 |
| `docs/data/jobs.json` | 版本 1 的公开岗位快照 |
| `tests/` | Node 内置测试 |
| `scheduler/` | 可选 macOS 定时采样、保守初筛和独立发布运行程序 |

快照中的 `run.cardsReviewed`（累计卡片）与 `run.detailsRead`（完整 JD）是按来源及岗位记录去重的累计查看数量，不是平台总量或已确认的独立招聘名额，也不随页面筛选改变。`selectedCount` 等于当前 `jobs.length`，`newCount` 等于 `isNew: true` 的当前岗位数。“本轮新增”仅依据 `isNew` 标记，不根据日期猜测；后续快照保留旧岗位的 `firstSeen` 与 `lastSeen`，不以评估调整或快照生成时间覆盖观察记录。

数据仍使用版本 1 的契约；方向别名和优先级排序不增加岗位字段。未知标量字段使用 `null`，未知列表使用空数组；未公布薪资时不补估值。`salaryText` 与 `salaryMonths` 可保留招聘页原文和标注薪数，同时让 `salaryMinK`、`salaryMaxK` 保持 `null`；数值筛选仅依据后两者，不从原文或薪数推算月薪或年薪。

来源仅支持以下三个明确分支，岗位的 `source`、`id` 和原始链接必须相互对应，不接受其他站点或跨来源链接：

| `source` | `id` | 允许的原始链接 |
| --- | --- | --- |
| `BOSS直聘` | `boss-<id>` | HTTPS 的 `zhipin.com` 及其子域下的 `/job_detail/<id>.html`；不得带查询参数、片段、凭据或非默认端口 |
| `字节跳动招聘官网` | `bytedance-<数字ID>` | 严格为 `https://jobs.bytedance.com/experienced/position/<同一数字ID>/detail`；不得带查询参数、片段或其他 URL 修饰 |
| `猎聘` | `liepin-<数字ID>` | 严格为 `https://www.liepin.com/job/<同一数字ID>.shtml`；不得带查询参数、片段、凭据、端口或其他 URL 修饰 |

数字 ID 始终按字符串处理。`run.source` 保持字符串类型，只允许上述三个单独来源，或明确的混合快照标签 `BOSS直聘 + 字节跳动招聘官网`、`BOSS直聘 + 字节跳动招聘官网 + 猎聘`。卡片分别标注实际来源并链接原始岗位，未确认的招聘状态、薪资和招聘名额仍需以源站确认为准。

`run.mode` 兼容原有单次、累计精选、人工扩展和定时规则快照。原有 `assessmentMethods` 按公开岗位 ID 标记 `human-assisted` 或 `rules-v1`，保留岗位的初筛方式不随发布者更换而改变。候选快照使用 `采样候选 · 累计快照` 及 `source-only` 方式，不包含私有匹配规则、个人背景或完整原 JD。

候选模式额外提供严格验证的 `candidateFeed` 和 `candidateStatesById`。前者记录发布类型（定时、受控、历史补展示或人工选入）、真实采样时点与有效卡片/完整详情计数，不把补展示时间冒充采样时间；后者只列采样候选的来源完整度、通用职责方向与该信息的观察时间。其余岗位为已选入线索。候选数量、已选入数量及本次首次展示数量由公开记录计算，私有队列不阻挡可见性。

`automation` 可选地同时提供 `reviewPendingThisRun` 与 `parsePendingThisRun`，仅表示本轮待复核总数及其中的结构解析待复核数。老快照没有这两个数值时会显示未记录，而不是假定为零。待复核不等于不适合或已入选，“新增 0”也不代表平台没有其他机会。

暂停期间的人工维护使用 `人工维护 · 已保存快照`，保留原 `generatedAt` 与所有保留岗位的观察时间；另以严格的 `publication` 状态记录人工发布时间和 `scheduler: "paused"`。页面会明确说明采集已暂停，不将维护发布当作重新采集。私人反馈和手动排除记录不进入公开快照。

旧模式 `publication.scheduler: "collection-only"` 仍只表示最近人工确认的仅采集模式，不能冒充候选自动发布。迁移后的候选快照改用 `candidateFeed`，不再显示事前审核阻挡公告。`firstPublishedAtById` 记录真实首次公开时间，用于今日/近7天及日期分组；旧记录回退到 `firstSeen`。重复观察、后续人工选入或无新增的成功采样都不重置首次展示日；卡片始终保留原首次观察时间。

## 检查

无需安装包，使用支持内置测试运行器的 Node.js：

```sh
node --test
```

GitHub Pages 使用 `main` 分支的 `/docs` 目录。所有资产和数据使用相对路径，兼容仓库子路径部署；无需构建服务、第三方字体或追踪脚本。

HTML 中的资产、入口模块的依赖与数据 URL 使用同一 `rev` 修订标记，发布更新时需同步变更，避免缓存中的旧模块读取新版数据。JSON 请求始终使用 `cache: "no-store"`。已打开的快照不会自动更新，重新加载页面后读取当前发布版本。

跨上海午夜或返回页面时，只根据当前时间重算已加载记录的日期视图、相对日期标题与时段提示；不重新请求数据、不触发采集、不清空当前视图或筛选。后台任务的时间与运行状态不受此展示功能影响。
